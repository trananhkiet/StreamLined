## Giả thuyết
[DOT (ICCV 2023)](https://github.com/megvii-research/mdistiller/blob/master/mdistiller/engine/dot.py): gradient của CE (task) và của distillation thường xung đột, và với một buffer momentum chung loss nào có gradient lớn hơn sẽ lấn át.
DOT giữ **hai buffer momentum riêng**: task loss dùng momentum nhỏ hơn (0.9 − delta), distillation loss dùng momentum lớn hơn (0.9 + delta), để distillation có ảnh hưởng đủ lớn lên quỹ đạo tối ưu.
Kỳ vọng DOT ≥ run B với **cùng loss**. Chưa biết hướng thật sự. Vì A1/A2/LS/DKD đều không vượt B, đây là hướng thay đổi thuật toán tối ưu thay vì loss, nên đáng thử.

## Thay đổi (một yếu tố so với run B: bộ tối ưu)
`OPTIM_MODE=dot`: `L_task = CE (×0.5)`, `L_distill = KD (×0.5) + BC (×0.5)` — đúng loss SKD của run B, nhưng backward riêng cho từng loss và cập nhật theo DOT:
`optimizer.zero_grad(); L_distill.backward(retain_graph=True); optimizer.step_kd(); optimizer.zero_grad(); L_task.backward(); optimizer.step()`.
`momentum_task = 0.9 − 0.075 = 0.825`, `momentum_kd = 0.9 + 0.075 = 0.975` (`DOT_DELTA=0.075`, mặc định của mdistiller), weight decay 5e-4 như run B.
**LR giữ 0.1 như run B** (config DOT gốc cho CIFAR-100 dùng LR 0.05) để đổi đúng một yếu tố.
Code DOT gốc (MIT) được chép nguyên vào notebook (chỉ bỏ import `torch.optim._functional` không còn trong PyTorch mới) để notebook tự đủ, không phụ thuộc mạng.
Code: `kaggle/streamlined_kd_cifar100.py` (default `OPTIM_MODE=sgd` = hành vi cũ), notebook `kaggle/experiments/d_dot.ipynb` (default `OPTIM_MODE=dot`).

**Rủi ro đã biết:** với momentum 0.975 cho phần distillation, bước hiệu dụng của phần này lớn gấp ~4 lần so với SGD momentum 0.9 ở cùng LR (1/(1−0.975)=40 so với 10), cả ở config gốc lẫn ở đây.
Ở LR 0.1 có nguy cơ mất ổn định sớm. Nếu test top-1 ~1% kéo dài hoặc loss NaN: ghi lại và chạy lại với `LR 0.05` (config gốc DOT; cần thêm env `LEARNING_RATE`) như một lần thử thứ hai nếu quota cho phép.
